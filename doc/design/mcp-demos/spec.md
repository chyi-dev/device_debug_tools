# MCP 功能设计 spec

三套初稿的共同输入。只写要说什么，不写长什么样。

## 项目

设备调试工具里的本机 MCP。人已经打开工作台，Cursor 连到这一进程。助手看现场、发一帧、等回包、起草脚本。热路径仍是 Lua。

## 受众与场景

坐在工位前的人，窗口 1440×900。串口上挂着传感器，蓝牙模组已经钉好 Notify 和 Write，MQTT 已连接。助手在旁边，人要看见它碰到了哪一条连接。

## 核心信息

- 本机 MCP 由人打开，默认只读。关着时，发送和写草稿都不发生。
- 每一帧写明目标连接。发到「传感器」不会因为当前页签是「模组」就改道。
- 单次发送落进该连接自己的数据日志：`SEND`，随后一条演示回包 `RECV`。串口未打开时拦住，文案与现有产品一致：「串口未打开，发送已拦截」。
- 快捷指令、自动应答、Lua 可以是草稿。能编译，停在待启用。启用由人在工具里打开。
- 校验对帧 `A5 5A 03 00 F5 01 2C` 出六种结果，不写端口。结果：SUM8 `24`，XOR `24`，LRC `DC`，CRC8 `AF`，CRC16 `B6 8F`（低字节在前），CRC32 `FA 86 9E 6F`。
- 循环发送被拒绝，并在「传感器」的日志里留一条系统消息。
- MQTT 只出现主题 `sensor`。密码显示为「已保存，不向客户端展示」。
- 日志仍是当前快照。状态栏写明画面最多保留 500 条。

## 演示数据

都来自现有产品里的传感器帧，不另编一台设备。

- 已在日志里的接收：`A5 5A 03 00 F5 01 2C`。按产品脚本课的读法，第 4–5、6–7 字节大端 ÷10，是 24.5 与 30.0。
- 助手请求发出的一帧：`A5 5A 01`。
- 演示回包：`A5 5A 03 00 F6 01 2E`。系统消息写明这是同一帧格式的演示，不是现场抓包。
- 草稿名 `parse_sensor.lua`，钩子 `on_receive`，状态「能编译 · 待启用」。产品里已有的第二条示例 `add_checksum.lua` 只在「允许写草稿」之后才会被助手放进来。
- 三条连接：传感器（串口 COM3，115200 N 8 1，已打开）、模组（蓝牙，Notify 与 Write 已钉）、遥测（MQTT 已连接，主题 `sensor`）。

## 情感基调

工作台还是工作台。助手是被看住的一双手，不是另一块产品介绍。

## 输出

- 尺寸：1440×900，一屏一个桌面窗口，铺满视口。
- 缩略图：六格，每格约 480×300，外加说明。
- 完整版三个，单文件 HTML，可点击。
- 外壳冻结：菜单栏、连接页签、左设置、中日志与发送、右工具、状态栏。token 用 `doc/shell-redesign/06-designer-console-evolved.html` 的白底经典。绿和红只表示连接与引脚。

## 每个完整版都要能点通

打开或关闭 MCP、改授权、发一帧并看见它落进「传感器」的日志、看见待启用草稿并可由人启用、看见循环发送被拒绝、对那一帧做校验、关掉串口后发送被拦住、切到别的页签后确认这一帧没有改道。

## form 五问

- 叙事角色：授权和痕迹，不是功能清单。
- 观众距离：一臂之内的桌面窗口。
- 视觉温度：与现有调试台相同的白底、发丝线、一个蓝。
- 容量：一屏。MCP 挤进现有骨架，不另做落地页。
- 视觉母题：日志行，以及「这一帧的目标连接」。

## 假设

- 客户端在界面里写成 Cursor，只用文字，不画标志。
- 三版配色相同。差异只在助手的手出现在哪。
- 此阶段不改 `lib/`，也不写 `direction-approved.md`。
